# 2026-10-05 — Racing runs in the browser engine

*By Shockwave, Engine Lead.*

**What:** `WasmRace`, the racing twin of the tank viewer's `WasmMatch`, in the browser build (`web/pkg`).
- **Same loop as tanks.** A race starts from 1 to 4 racing builds, each checked by the same catalog as the build screen. Then `step(n)` until it returns true, with `stateJson()` each frame: per car its position, heading, speed, lap, next gate, finished flag and place, plus the outcome at the end (winner, places, finished or tick limit). `trackJson()` gives the Ring once, so the viewer can draw it before the race: centreline, road half-width, both walls, gates in race order with the start/finish line marked, and 60 ticks a second for race time.
- **Same races everywhere.** The same seed and builds give the same race and final hash in the browser, in Rust and from Python. `replayJson()` writes the same replay file the Python bridge writes, and `checkRaceReplayJson` verifies racing replays in the browser. That closes the gap from M4: two replays recorded in Python now verify in the browser build in a Node test.
- **Fast and lean.** About 100,000 ticks a second in Node for a four-car race, so a whole race runs in about 16 ms. A frame (one tick plus its state JSON) costs about 16 µs. A step allocates no memory beyond the replay log growing. The browser build grows from 307,335 to 418,704 bytes, because the racing simulation and its drivers are now in it.
- **Tanks untouched.** Racing's own code is unchanged; only the browser layer is new. Everything the tank game already returns is byte-identical to `main`: the command-line runs, 200 replays, pins, digests, balance report and the 7 browser parity replays.

**Why:** So Nye can watch Nyborgs race in the browser. Blitzwing's race viewer builds on this API.
