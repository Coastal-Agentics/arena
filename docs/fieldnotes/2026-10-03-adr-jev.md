# 2026-10-03 — Proposed: Jev as an optional tool (ADR-015)

*By Shockwave, Engine Lead.*

**What:** A proposed decision record, ADR-015 in `docs/DECISIONS.md`, on how we would use Jev, TypeSafe AI's fast structured-decision model. It answers typed questions (pick an option, pick a rubric level, or a 0–1 truth value) about a state written as text. Docs only: no code, no dependencies, no account.
- **Outside the tick.** Jev may score replays after the fact, guard LLM-written content, and play a slow "strategist" opponent in headless matches. It never runs inside the 60 Hz tick: its claimed latency is 4 to 30 ticks, and its answers vary a little from run to run.
- **Logged.** Every answer is recorded with the match, with a pinned model version. Replays, the parity fixtures and CI read the log and never call the service, so "same seed, same match" still holds.
- **Never a training source.** Jev's output is never used to train a model by imitation or distillation; its contract (section 2.3(b)) forbids that. Using its scores as a reward or a fitness is not allowed until the company's attorney clears it.
- **No key needed.** The arena and Saltmarsh run without an API key. Jev would sit behind a swappable interface, next to local constrained-decoding models and behavior trees. The company, not Nye personally, would hold the account, and nothing is added until Nye approves.

**Why:** Nye asked for a clear rule on whether and how Jev fits before anyone signs up or adds a dependency. The research came from Reflector.
